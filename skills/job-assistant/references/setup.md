# setup：从真实经历建档

交付 `profile.md`、`preferences.json` 与初步 `tracks.md`。先按 runtime.md 初始化。

1. 只读取用户本次指定的简历/材料；用户明确指定文件已构成读取授权，不再重复问同一权限。未指定、散落在目录里的私人文件不主动扫描内容。
2. 使用可用提取工具逐份读取并保留来源位置。多个来源取并集，保留只存在于某一份材料的事实。表格、时间线、扫描页提取残缺时说明缺口并请求补文本。
3. 把可疑的动词、数字、角色归因、时间冲突集中列成待确认清单。用户明确认可整份材料时可批量确认无歧义条目；已确认事实不重复确认。未经确认的保留为“待确认”，不得流入对外稿件。
4. 每条使用稳定事实 ID（F001 等），记录来源文件/位置或“用户确认 日期”、确认状态、公开范围。数字补齐基线、单位、周期、本人贡献；不能讲清的用保守的真实表达，不编提升比例。
5. 记录目标岗位、地点与薪资等偏好。只问影响当前工作的必要信息；薪资必须同时有币种、周期、税前/税后/总包口径，信息缺失不据此否决岗位。地点和出差限制未知时标未知。
6. 依据用户目标与事实建立一个或多个方向，不预设项目经理、年限或转型意图。[可选转型预设](presets.md) 只在用户明确想转型且相关时读取。
7. 用户修正原事实时增量更新并留修订记录；已投材料不回改。指出可能受影响的现有稿件，后续修改用新版本。

无简历时按教育、工作、项目、结果、技能逐步访谈，不一次抛完整问卷。没有量化结果允许使用可核实的定性结果，不要求用户凑数字。
完成时汇报已确认事实、待确认项和当前目标；可直接评一个 JD，也可继续方向诊断。
